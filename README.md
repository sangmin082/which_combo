# 🎲 위치, 콤보! (Which Combo)

넷플릭스 예능 **〈데스게임〉**의 게임 "위치, 콤보!"를 iOS 게임으로 구현한 프로젝트입니다.
([기억의 만찬](https://github.com/sangmin082/feast_of_memory)과 같은 구조 — SwiftUI 앱 + Node.js 릴레이 서버)

- **1인용** — AI와 암기 대결 (난이도 3단계). 규칙대로 **스크린샷 등 기록 행위를 감지하면 즉시 몰수패**(암기 위반)합니다.
- **2인용** — 방을 만들면 6자리 방코드가 생성되고, 친구가 코드를 입력해 입장하면 실시간 온라인 대결이 시작됩니다.

## 게임 규칙

> 5×5 게임판의 **숫자 위치를 암기**하고, 숫자를 조합해 **더 강한 족보**를 만드는 게임.

1. **게임판 설정** — 각 플레이어는 5×5 게임판(A1~E5)을 지급받는다. 선 플레이어부터 번갈아,
   1~10이 적힌 10면체 주사위를 굴려 나온 숫자를 자신의 게임판 빈 칸에 하나씩 배치한다 (각자 25칸).
2. **암기** — 설정이 끝나면 숫자는 모두 가려진다. 이후에는 오직 암기로만 족보를 선언한다.
   물리적으로 기록하면 몰수패.
3. **족보 제출 (12라운드)** — 자신의 게임판에서 가로/세로/대각선 중 한 방향으로 이어진 4칸을 골라
   족보를 선언한다. 이미 선언한 조합은 재사용 불가. 매 라운드 선언 순서는 교대하며,
   제한 시간 1분을 넘기면 남은 라인 중 하나가 무작위로 선언된다.
4. **족보 순위** — ① 쿼드(1,1,1,1) ② 로얄 스트레이트(1,2,3,4) ③ 스트레이트(1,3,2,4)
   ④ 투페어(1,1,2,2) ⑤ 트리플(1,1,1,2) ⑥ 원페어(1,1,2,4) ⑦ 하이(1,3,5,7).
   같은 조합이면 사용한 숫자가 높은 쪽이 승리, 숫자마저 같으면 무승부.
5. **승리** — 족보가 높은 쪽이 승점을 획득하고, 12라운드 종료 시 승점이 높은 쪽이 승리한다.

## 프로젝트 구조

```
WhichCombo.xcodeproj         Xcode 16+ 프로젝트
WhichCombo/
├── App/WhichComboApp.swift
├── Game/
│   ├── GameEngine.swift     규칙 상태기계 (순수 값 타입 — 양쪽 기기에서 동일 재현)
│   ├── AIPlayer.swift       불완전 기억 모델 기반 AI (쉬움/보통/어려움)
│   ├── GameViewModel.swift  대국 진행, 주사위, 60초 타이머, 공개/커버 연출, 암기 위반 처리
│   ├── StatsStore.swift     전적 저장
│   └── EngineSelfTest.swift 라인 테이블·족보 판정·대본 대국 리플레이 검증 (DEBUG)
├── Online/RoomClient.swift  WebSocket 클라이언트 (방 생성/코드 입장/무브 릴레이)
└── Views/                   홈, 대국 화면(5×5 게임판 2개), 온라인 로비, 규칙, 전적
server/
├── index.js                 2인용 릴레이 서버 (Node.js + ws)
└── test.js                  서버 통합 테스트
```

## 실행 방법

### iOS 앱 (Xcode 16 이상, iOS 17+)

```bash
open WhichCombo.xcodeproj
```

시뮬레이터나 기기에서 Run. DEBUG 빌드는 시작 시 엔진 셀프테스트를 자동 실행합니다.

### 2인용 서버

앱에는 기본 서버 주소(`OnlineConfig.defaultServerURLString`)가 내장되어 있어 사용자는 방 코드만 주고받으면 된다.

**클라우드 배포 (Render 무료 티어)**

1. [render.com](https://render.com) 가입 (GitHub 로그인)
2. New → **Blueprint** → 이 저장소 연결 → `render.yaml`이 자동 인식됨 → Deploy
3. 배포 완료 후 주소 확인 (서비스 이름이 `which-combo`면 `wss://which-combo.onrender.com`)
4. 주소가 다르면 `WhichCombo/Online/OnlineConfig.swift`의 기본 주소를 수정

무료 티어는 15분간 접속이 없으면 잠들며, 다음 접속 시 깨어나는 데 최대 1분 걸린다 (로비에 안내 문구 표시됨).
`.github/workflows/keepalive.yml`이 10분마다 서버를 핑해 슬립을 방지한다.

**로컬 실행/테스트**

```bash
cd server
npm install
npm start        # ws://0.0.0.0:8080  (헬스체크: http://localhost:8080)
npm test         # 통합 테스트
```

다른 서버를 쓰려면 `OnlineConfig.defaultServerURLString`을 수정해 빌드한다.

## 구현 노트

- **온라인 동기화**: 서버는 무브를 해석하지 않는 단순 릴레이입니다. 엔진이 결정적(deterministic)이라
  같은 무브 스트림이면 양쪽 상태가 항상 일치합니다. 주사위 값은 배치하는 쪽 기기가 굴려
  `place` 무브에 실어 보냅니다. 선(先)은 서버가 랜덤 배정합니다.
- **라인 테이블**: 5×5 게임판에서 한 방향으로 이어진 4칸 조합은 가로 10 + 세로 10 + 대각선 8 = 총 28개입니다.
  12라운드 동안 각자 12개를 소모하므로 항상 선언 가능한 라인이 남습니다.
- **로얄 vs 스트레이트**: 라인 방향 순서 그대로 읽었을 때 매 칸 +1(또는 -1)씩 연속이면 로얄 스트레이트,
  연속된 4개 숫자지만 순서가 뒤섞여 있으면 스트레이트로 판정합니다.
- **AI**: 실제 게임판을 훔쳐보지 않고, 배치 과정을 관찰해 만든 자기 "기억"만으로 선언합니다.
  난이도에 따라 기억 유지율과 망각 확률이 달라지며, 배치 단계에서는 쿼드/스트레이트 잠재력을
  점수화해 자리를 고릅니다. 라운드 후공일 때는 이길 수 있는 가장 약한 족보로 승점을 노립니다.
- **암기 위반**: `UIApplication.userDidTakeScreenshotNotification` 감지 시 해당 플레이어 몰수패로 처리합니다.
- **TestFlight/수익화**: 필요해지면 [feast_of_memory](https://github.com/sangmin082/feast_of_memory)의
  `fastlane` + GitHub Actions 구성과 AdMob/IAP 코드를 같은 방식으로 가져오면 됩니다.
